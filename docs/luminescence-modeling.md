# 蕾米埃尔·丹队伍异常评分建模

## 1. 目标与输入

本模型用于比较蕾米埃尔·丹（`remielle_dan`）的候选驱动盘，不还原游戏中的实际伤害。
首版固定三异常队和额外能力生效，只计算一个普通虚曜。玩家只需要输入：

- 队友接受丹攻击力共享前的初始攻击力；
- 耀变伤害在队伍异常总伤害中的经验占比，默认 `50%`。

经验占比用于表达耀变相关收益在驱动盘排序中的权重。它不要求玩家提供测量构筑的异常
精通、耀变增伤或其他参考快照，也不保证每套候选盘的实际耀变占比始终等于该数值。

队友配装、原异常倍率、固定招式倍率、触发次数和抗性等不会随丹候选盘变化的因素合并为
正数常量 `k`。敌人防御、失衡、特殊虚曜和多虚曜时序不进入评分。

## 2. 正式恒定权重模型

对候选驱动盘 `d` 定义公共基础因子：

```text
B(d) =
[T + min(0.40 * A(d), 1600)]
* [1 + 0.10 + 0.20 * I(M2) + 0.0002 * P(d)]
```

定义异常增伤和耀变专属因子：

```text
E    = 1 + e
M(d) = 1 + e + s(d)
H(d) = 1 + alpha * P(d)
R(d) = H(d) * M(d) / E
```

- `T`：队友接受丹攻击力共享前的初始攻击力；
- `A(d)`：丹在候选盘下的最终局外攻击力；
- `P(d)`：丹在候选盘下的当前局内异常精通；
- `alpha`：初始/A/B/C/D/E/F 核心技对应的
  `0.0010/0.0012/0.0014/0.0015/0.0016/0.0018/0.0020`；
- `e`：场地或 Boss 提供、抽象队伍其他异常伤害同样获得的宽泛属性异常增伤；
- `s(d)`：专武、个人驱动盘等只在丹的耀变侧生效的属性异常增伤；
- `E`：全队公共异常增伤倍率；
- `M(d)`：耀变实际获得的完整同桶异常增伤倍率；
- `R(d)`：耀变相对于其他异常伤害的倍率优势；
- `w`：耀变的恒定经验权重，默认 `0.50`。

正式评分为：

```text
队伍异常评分(d) = B(d) * E * R(d)^w * k
                 = B(d) * E * [H(d) * M(d) / E]^w * k
```

等价展开为：

```text
B(d) * E^(1-w) * [H(d) * M(d)]^w * k
```

网页使用第一种写法。它直接显示公共环境倍率完整作用于全队，再把耀变相对其他异常伤害
多出的倍率按经验权重计入。旧的参考构筑加法模型仅作为具名内部函数保留，不进入网页、
存档、Worker、服务端或正式优化器。

## 3. 为什么使用指数权重

当耀变在当前队伍伤害中的经验占比为 `w` 时，耀变专属倍率发生小幅变化，队伍总伤的
对数变化近似为：

```text
d ln(D_team) ~= d ln(B) + d ln(E) + w * d ln(R)
```

因此 `R^w` 是不依赖未知参考构筑的恒定权重近似。它适合比较相邻驱动盘方案，但不是把
两条实际伤害分支精确相加，也不会宣称候选盘更换后耀变仍严格占总伤 `w`。

`w=0%` 时，耀变专属因子不影响评分；`w=100%` 时，公式回到完整耀变侧：

```text
w = 0: B(d) * E * k
w = 1: B(d) * H(d) * M(d) * k
```

## 4. 场地 Buff 与同桶增伤

假设环境提供 `16%` 宽泛属性异常增伤，专武和个人驱动盘合计提供 `35%`：

```text
E    = 1 + 0.16 = 1.16
M(d) = 1 + 0.16 + 0.35 = 1.51
M(d) / E = 1.51 / 1.16
```

属性异常增伤位于同一加算桶，因此 `M(d)` 是 `1.51`，不是 `1.16 * 1.35`。`1.51/1.16`
本身已经是完整相对倍率，不能再写成 `1 + 1.51/1.16`。

当 `w=0.50`、F 核心时，白盒显示：

```text
B(d)
* 1.16
* ([1 + 0.002 * P(d)] * 1.51 / 1.16)^0.50
* k
```

外层 `1.16` 完整计入评分，所以勾选正向公共环境 Buff 不会因为相对优势被稀释而让显示
分数反向降低。与此同时，`1.51/1.16` 会正确表达环境增伤对个人 `35%` 增伤优势的稀释。
在环境固定且所有候选盘的 `s(d)` 相同时，外层公共倍率不会改变排序；候选盘改变个人异常
增伤时，完整同桶倍率仍会影响排序。

只有 `sourceType: "field" | "boss"`、目标为宽泛默认作用域、无具体属性/异常/结算限制且
无角色条件的 `anomalyDamageBonus` 才进入 `E`。专武、个人驱动盘、角色自身、队友、自定义
Buff，以及带具体目标或条件的场地/Boss 规则只在确实命中丹时进入 `M(d)`，不得扩大到抽象
的其他队友异常伤害。

## 5. 事件与兼容

正式事件只持久化：

```json
{
  "id": "remielle_normal_voidflare_vertical_rainbow",
  "kind": "anomaly",
  "settlementType": "luminescence",
  "triggerActorRef": { "agentId": "remielle_dan" },
  "teammateAttack": 2800,
  "luminescenceDamageSharePct": 50
}
```

`teammateAttack` 必须为有限非负数；`luminescenceDamageSharePct` 必须为 `0..100` 内的有限
数。旧事件优先迁移 `teammateAttack`，其次读取首条普通记录的 `T`，缺失时使用 `2800`；
缺失占比时使用 `50`。旧的参考构筑、记录、倍率、属性、抗性、招式和特殊虚曜字段允许
兼容读取，但再次保存时必须删除。

运行时 `teamAnomalyDamageMultiplier` 与 `luminescenceDamageMultiplier` 完全由当前候选盘和
已选择 Buff 派生，不作为事件输入持久化。结果使用
`objectiveKind: "luminescenceTeamScore"` 和后缀 `× k`。旧 `luminescenceScore` 只作为显示
兼容值识别。队伍异常评分必须单独作为标量优化目标，不能与实际伤害事件相加。

## 6. 白盒与回归契约

白盒只显示“队友初始攻击力”“丹局外攻击力”“丹局内异常精通”“耀变在队伍总伤害中的
占比”“异化倍率”和完整评分公式。前三项面板字段与占比字段不再附带重复的小字说明；
“异化倍率”必须展平显示当前影画与异常精通代值，例如
`1 + 0.10 + 0.20 + 0.0002 * 612 = 1.4224`。存在公共环境增伤时，评分公式必须展平显示：

```text
B(d) * E * [H(d) * M(d) / E]^w * k
```

没有公共环境增伤时可以省略无意义的 `* 1` 和 `/ 1`。事件页在占比输入下提示玩家可以
参考危局结束时蕾米埃尔的伤害占比，并在绝大部分情况下将其视为耀变占队伍总伤害的占比。
事件预览与白盒评分说明统一采用以下建模口径：丹所在队伍伤害的最大化，主要取决于队友
攻击力、队友其他属性（如异常精通、穿透等）、耀变伤害占比、丹初始攻击力、丹局内精通；
将队友攻击力、耀变伤害占比设置为变量，将队友其他属性设置为恒变量 `k`，从而得到关于
丹攻击力以及异常精通配置的最优解。界面不得显示参考构筑、归一化、多虚曜、原异常倍率、
抗性口径或特殊虚曜配置。

普通、白盒、compiled、dense、固定评分、浏览器 Worker、服务端和严格优化器必须使用同一
正式评分函数。正向公共环境异常增伤不得降低同一候选的显示评分。保留的旧加法模型只允许
由独立核心单测和内部对比工具覆盖，不得进入正式结果。
