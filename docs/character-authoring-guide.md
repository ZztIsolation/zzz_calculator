# 角色制作与维护指南

状态：现行工作流程。核对日期：2026-10-08；基准提交：`6355fbd310cc5836aff0e78bc3fb46e68a5356f8`。

目标是首轮交付完整可用的角色，由制作者先完成内部检查，再集中验收。
本指南记录制作方法和历史教训；完整语义见[建模说明](modeling.md)，具体不变量和测试见[回归契约](regression-contract.md)。
角色事实、项目假设、用户配置和实现缺陷应分别识别，不能用测试通过掩盖机制误读。

## 阶段一：资料核对

先检查当前分支、工作区差异、目标角色目录、最近相关提交和测试。已有的手工维护记录是工作起点，不是待覆盖的导入残留。

资料以官方结构化内容为主要依据，记录角色/装备条目ID、修订号、URL和获取时间。
动态百科可先在浏览器打开页面，再在同一上下文读取 `entry_page` 接口，带 `x-rpc-wiki_app: zzz` 和官方 Referer；解析结构化技能表，不从截图或DOM片段推测完整数值。
该方法是采集入口，不保证所有未来页面结构相同，必须核对返回的角色和版本。

检查项目包括：

- 初始面板是否包含核心技节点；角色、音擎、核心白值分开，避免重复叠加。
- 所需等级的伤害、失衡、回复表是否完整；补充等级必须有明确来源，不擅自外推。
- 每个核心档位、影画、潜能和精炼档位；检查百分比、固定点数和单位。
- 资料中的明显错位、重复或跨来源差异；原始值与采用依据一起保留。
- 描述中未公开或当前模型不支持的机制，标明未建模，不伪造技能ID或数值。

重要采集差异放入目录的来源/校验信息及必要fixture；可参考[佩洛伊斯来源fixture](../tests/fixtures/pyrois-source-values.json)。
正文摘要不替代结构化数据，也不以旧导入脚本覆盖人工改过的整条记录。

## 阶段二：机制映射

实现前逐条填写效果清单，至少包含：

| 原文效果 | 来源归属 | 触发条件 | 作用目标 | 面板来源 | 乘区/字段 | 成长/上限 | 默认状态 | 建模边界 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 完整条款及来源 | 核心/额外/影画/招式/装备/队友 | 是否失衡、层数等 | 招式/倍率行/结算 | 初始、局内或外部快照 | 对应现有语义 | 档位、阈值、覆盖率 | 启用、层数、参数 | 已支持、明确假设或未建模 |

先复用现有语义：普通增伤与技能倍率加算不同；穿透、无视防御、降防不同；属性异常、紊乱、异放、乱流不同。
技能来源Buff按真实来源归类，不能看到招式名称就创建独立开关。
核心成长只维护一张结构化表；自动面板来源不增加重复手填控件。

新的伤害域需要完整接入，而不是给旧公式换名称或基础属性。
异常来源和触发者分开；不同贡献者先计算完整伤害，再聚合，不能先平均非线性输入。
效果只影响部分子段时，计算总倍率必须保留分段目标。

只集中询问会改变结果且无法从既有决定推导的假设，例如默认计算目标、未知机制和资源处理。
已确定的快照口径、描述格式、维护保护等由制作者直接落实，不反复要求确认。

## 阶段三：使用配置

先描述“选中该角色之后用户应该看到什么”，再完成数据：

- 计算目标：单技能、单次异常/异放、固定事件组合，或独立评分。
- 技能组：名称可读、包含内容准确；连携、附带攻击、追击不得隐藏在无说明的组里。
- 默认方案：可以直接计算，次数与失衡状态明确；需要时才设置影画或潜能变体。
- Buff：正确归属、合理默认启用、层数和覆盖率，说明包含条件、范围、档位和上限。
- 推荐音擎、4件套、2件套、主词条候选、重要副词条和重要面板属性。
- 必要的头像、图片来源、专属关联和Enka身份映射。

游戏解锁说明、计算器允许选用的事件、实际获得的数值成长是不同维度。
例如11号P0允许选已录入潜能招式，但不会得到P2-P6数值；单组追加上限也不能限制技能组重复总数。

管理员默认循环并非必填。薇薇安的单次自源异放可以由非管理员fallback生成；不要为了“内容完整”制造无依据的整套循环。
复杂机制可以保留在底层，当前角色固定的来源或基底由系统推导，界面只暴露有意义的选择。

## 阶段四：完整接入

按影响检查以下链条，不能只完成目录录入：

| 链条 | 检查内容 |
| --- | --- |
| 目录与维护 | 当前schema、引用、中文标签、动态成长、清洗/校验、保存回读 |
| 普通计算与白盒 | 面板、事件、作用与排除目标、分段、单位、来源解释 |
| 编译和优化 | prepared/compiled/dense/固定套装、候选依赖、相关词条、安全上界 |
| Worker | Node与真实浏览器的消息、结果、进度、取消和复用 |
| 状态与存档 | 角色/核心/影画/潜能切换，旧ID迁移，手动取消项和自定义配置 |
| 展示与导入 | 本地资源、缩略图、推荐关联、Enka映射和别名 |

常用入口：[计算核心](../core/calculator-core.js)、[维护校验](../core/maintenanceValidation.js)、[角色编辑器](../webapp/src/components/maintenance/editors/AgentEditor.vue)、[构筑状态](../webapp/src/stores/build.ts)、[优化器](../core/driveDiscOptimizer-core.js)。

图片变更按根README说明生成并校验缩略图。目录存在不等于Enka可导入：检查映射快照、别名适配、解析fixture和前台结果。
本地服务或静态目录可能缓存旧数据；用当前catalog/API响应核对消费者，不能只检查磁盘文件。

## 阶段五：验证验收

验证应证明行为，而不是逐行复述实现。先运行受影响的聚焦测试，再完成共享逻辑或发布所需的检查；通过后不无理由重复整套测试。

| 场景 | 必须证明的内容 |
| --- | --- |
| 独立算例 | 根据来源与公式独立算出预期值，区分局外/局内输入与单位 |
| 作用与反例 | 应命中的招式受到效果，不应命中的招式、属性、结算保持隔离 |
| 边界 | 等级首末档、阈值两侧、零/部分/满覆盖、层数和次数上限 |
| 总倍率和重复组 | 总事件与独立子段求和一致；每组合法次数聚合后仍正确 |
| 评分路径 | 普通、白盒、compiled、dense、固定评分与实际优化目标一致 |
| 严格搜索 | 小规模独立穷举核对完整Top 10 ID、顺序、分数容差和不足10套情况 |
| 维护往返 | 编辑、取消、应用、保存、刷新、重新打开；失败草稿和旧版本冲突 |
| 浏览器使用 | 新选角色、切等级、切模式、手动改配置、刷新恢复；桌面与窄屏无裁切 |

执行入口由 [package.json](../package.json) 和[回归契约](regression-contract.md)维护。
测试通过不能证明某个条件假设符合原文；只比较两个共享同一错误的内核也不能证明正确。
真实游戏验证、来源审查、自动测试和浏览器验证在交付说明中分别记录。

## 阶段六：交付保护

发布候选形成前，按角色ID和字段比较目录差异，明确新增、修改和删除的去向。
特别核对人工调整的技能组、默认循环、描述、重要属性和删去的空影画条目。
行数变化或JSON重排不能代替语义比较；不要把完整脏目录直接搬到只发布单个角色的分支。

维护保存、Git提交、进入发布产物、线上生效是四个独立事实。
获得发布授权后再按[发布手册](production-deployment-runbook.md)核对冻结SHA、产物和实际目录。
修订文档时同步当前配置；测试需要固定旧场景时构造专门fixture，不要求用户恢复旧默认方案。

首轮交付说明至少包括：

- 已支持的目标、机制和配套功能。
- 采用的假设、未公开/未建模部分及其影响。
- 默认事件/技能组、关键开关与推荐设置的简短说明。
- 实际验证结果、未完成的验证和保存/迁移边界。
- 与既有人工维护内容的核对结果。

## 七个案例

以下记录发生过的建模修正，并指向当前仓库证据。历史版本不是可直接重放的模板。

### 爱芮

- 初版问题：异放分类、原异常来源和触发者容易混在普通异常形态里；“初始属性”也容易被局内增益替代。
- 后续修正：异放独立为结算类型，保留来源/触发者语义；玩家编辑器只开放当前已支持的选择，白盒减少重复转换行。
- 可复用原则：先定义归属与面板来源，再设计字段；底层可扩展不意味着玩家界面必须暴露所有组合。异放比例与一影暴击转换的取整规则分别验证。
- 证据：[Release模型](../core/anomalyRelease.js)、[爱芮回归](../tests/aria-damage.test.js)、[事件编辑器](../webapp/src/components/CalculationConfigModal.vue)；历史提交 `e59aca1`、`aac4536`。

### 希格莉德

- 初版问题：将连携藏进敛枪组合、将砥砺归入核心，会影响独立选择；普通攻击总倍率还需要处理只命中子段的穿透。
- 后续修正：技能组改为纯敛枪，连携单计；砥砺成为准确的技能来源Buff；生成总事件在内核逐段匹配后求和。
- 可复用原则：组边界、来源归属和总事件内部计算都必须可审计，不让一个方便按钮改变机制。
- 证据：[希格莉德测试](../tests/sigrid-damage.test.js)、[白盒测试](../tests/damage-whitebox.test.js)、[当前目录](../data/agents.json)；`8091a37 → 184a38f`。

### 11号

- 初版问题：潜能招式的游戏解锁说明被用于限制计算器选择；每组机制限制与组重复次数混用；初始参考轴未反映后续维护需求。
- 后续修正：保留各潜能的数值成长，放开已录入招式选择；逐组验证追加次数，再计算聚合值；保留“火刀”命名和手工默认方案。
- 可复用原则：不要扩大一个有边界的需求；招式可选性、成长、次数、游戏说明分别处理。
- 证据：[潜能物化](../core/potentialVision.js)、[组展开](../core/calculationSkillGroups.js)、[11号测试](../tests/soldier-11-damage.test.js)；`7d0e2a6 → 8651b0b`。

### 薇薇安

- 初版问题：既有角色的管理员循环模式不能直接套用到单次自源异放；普通计算一致也不能保证严格优化的候选集合完整。
- 后续修正：使用目标明确的非管理员单事件fallback；二影只修饰精通转换；严格搜索保留合法候选并用独立穷举核对。
- 可复用原则：先锁定要优化什么，再决定录入范围和默认配置；独立验证完整结果集。
- 证据：[薇薇安回归](../tests/vivian-damage.test.js)、[优化器回归](../tests/optimizer.test.js)、[构筑状态](../webapp/src/stores/build.ts)；`22b74a4 → a90cc35`。

### 克拉蕾

- 初版问题：专属字段过多、普通暴击率与锐化语义混用、局外属性和快速路径遗漏；发布拆分还曾漏带维护删除。
- 后续修正：独立Sharp域贯通面板、事件、白盒和优化；以事件类型推导行为；默认循环表达影画差异；最终目录保留人工删除。
- 可复用原则：新域完整接入，自动值不交给维护者手输；交付时把有意删除与新增功能同等核对。
- 证据：[Sharp核心](../core/sharpDamage.js)、[Sharp测试](../tests/sharp-damage.test.js)、[发布打包](../scripts/package-server-release.js)。`87258ef`的目录只有1/2/4/6影，`744ddbd`加入六影循环时重新含有3/5影；后续 `fe403bc` 目录恢复人工删除，可用Git逐记录对照。

### 佩洛伊斯

- 初版问题：四分支都有倍率并不代表Buff归属、默认条件和技能组合正确；初始样例与后来维护方案不同，说明也曾落后于数据。
- 后续修正：四分支统一核心被动，明确快照条件，补全描述；技能组和默认循环按维护结果收敛，另补展柜映射。
- 可复用原则：先做效果归属表，并检查额外攻击是否真的在组内。旧ID带有 `with_directive` 也不能代替读取子事件。
- 证据：[角色专题](pyrois-modeling.md)、[回归](../tests/pyrois-damage.test.js)、[前端状态回归](../webapp/src/stores/pyrois-modeling.test.ts)；`febfc44 → 91d2854`、`080ad12`。

### 维琳娜

- 初版问题：风化、乱流和异放的来源及乘区容易混淆；通用来源字段增加维护负担；能量派生公式还必须随每套候选变化。
- 后续修正：区分非风基底与自身伤害，异放只选择必要来源；完善核心成长、六影继承排除和快速评分；保留人工“单次风化”默认目标。
- 可复用原则：自动推导固定信息，对真实变量给出可操作输入；当前默认由维护目录决定，不能被早期迁移恢复。
- 证据：[风属性专题](wind-anomaly-modeling.md)、[维琳娜测试](../tests/velina-damage.test.js)、[优化测试](../tests/velina-optimizer.test.js)、[维护API测试](../tests/agent-maintenance-api.test.js)；`68e49d5 → bda2d1c`。

## 已形成的维护习惯

- 名称简短易识别；描述完整交代触发、目标、成长和上限，两者分别服务操作和核查。
- 技能组服务常用组合，默认方案能直接使用，但不模拟未授权的队伍时间轴。
- 核心档位、面板派生、固定来源和兼容值由系统同步，减少重复输入。
- 优先装备和重要属性随角色一起完成；重要属性只影响展示，不能变成优化权重。
- 表单保留清晰分区；长默认循环采用摘要及主从弹窗；中文标签、步进器、保存按钮不能裁切。
- 取消不污染草稿，保存失败保留内容，独立字段合并、同字段冲突明确选择；目录删除不能在发布中复活。
- 一次交付的标准包含维护与使用，而不仅是“录入数据”和“测试通过”。
