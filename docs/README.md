## 修改后更新哪里

| 变化 | 主文档 | 同步内容 |
| --- | --- | --- |
| 通用计算语义 | 建模说明 | 对应回归条款及现有测试入口 |
| 角色特有公式或假设 | 角色专题；没有专题时使用角色回归条款 | 只有形成通用经验才补制作指南 |
| 人工维护技能组、默认循环或推荐值 | 角色专题或角色回归条款 | 核对当前目录、简洁记录变化，不重跑旧导入器 |
| 布局、维护交互 | 布局契约或维护回归条款 | 受影响的实际浏览器场景 |
| 工作流、部署命令或期限 | 发布、管理器或恢复手册中对应的主位置 | 其他文档链接及参数摘要 |
| 版本交付 | 变更日志 | 必要时进入双语README最近更新 |

每条完整规则只在一个主位置维护，其他文档引用。公式专题解释推导；回归条款只保留验收边界和必要的数值反例。
避免把角色默认值、公式全文、完整类型声明或生产命令复制到多个模板。

更新现行规范时记录实际核对日期、基准提交和证据类型。来源版本写入相应目录/fixture；不把旧测试数、缓存分支或发布记录当作新验证。
README的日期与用户可见事实保持中英文对应，历史叙述无需伪装为现行功能。

冲突处理：先区分官方机制、已确定的建模假设、管理员当前配置和程序行为。
有明确后续决定且实现吻合时更新旧说明；无法确认时在对应专题列出“待核实”、复现入口及差异，保留数据，另行处理业务修复。

## 文档验收

- 检查目录、链接、锚点、源码入口、命令和工作流参数。
- `git diff --check`，并核对差异仅包含本次授权内容，避免整文件换行噪声。
- `npm run test:repository-integrity` 检查资源和README必须保留的致谢。
- 发布文档引用的工作流通过 `node scripts/validate-deployment-config.js` 静态核对；该命令不发布生产。
- 文档修改不需要新增业务测试；代码改动仍按对应影响运行必要验证。
